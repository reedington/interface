**Project audit — 23 September 2026**

Audited revision: `ca2df7d6b2d7d4ae24315a0ce7501512db52eb25` (version 0.5.0). The working tree was clean before this audit. This report is the only repository change made by the audit.

**Verdict: a substantial, working local assessment implementation, with three reproduced correctness gaps.** The project implements the full discovery → artifact → replay → intervention sequence. It is considerably further along than the planning documents suggest. The earlier pasted audit was too confident that the remaining problems were merely presentation issues. Fix the request-binding and recovery defects, and validate artifact integrity at replay admission, before calling the implementation fully verified.

The audit used the supplied assignment PDF, source, tests, plans, README, REPORT, public evidence and a read-only re-export from retained private history. No new paid discovery, Mifos business operation, publication or submission was performed. Custom probes used a temporary synthetic lab and removed its database afterward.

**Findings, in priority order**

1. **The lab can commit different details from the approved preview.** Safety/correctness; fix first. In [engine.ts](../src/server/engine.ts), line 93, outgoing-body validation is conditional on a profile implementing `validateCommit`. The [lab profile](../src/server/targets/lab.ts), lines 47–54, allows `POST /applications` but supplies no body validator. The interface itself makes the validator optional in [types.ts](../src/server/targets/types.ts), line 32.

   Reproduction: prepare a synthetic application for member `10001`, wait for approval, change only the target form's hidden `clientReference` to `10002`, and approve the still-visible `10001` preview. The target persisted one application for **10002**. Only afterward did verification report `OUTCOME_UNKNOWN`. Detecting a mismatch after the write does not enforce the approved action.

   This is a controlled target-form fault injection, not an observed incident or a claim that ordinary clicks always produce the mismatch. Its scope is the supported lab profile; Mifos does implement request-body validation. Make exact-body validation mandatory for a profile that permits commits, deny commits without it, and add a regression asserting zero writes for mismatched hidden fields.

2. **Restart recovery ignores unfinished runs outside the latest 100 records.** Recovery correctness. [store.ts](../src/server/store.ts), line 40, recovers unfinished runs by calling `runs()`, but that method uses `LIMIT 100` at line 50. A long-waiting run can age outside that window while the other permitted session completes further work.

   Reproduction: save an unfinished run with `effect: unknown`, append 100 completed runs, close the store, and reopen it. The old run remained `status: running`, `owner: automation`, with no recovery outcome, and was absent from recent history. Its browser no longer exists; reconciliation requires a completed run, so it cannot enter normal recovery.

   Query all unfinished rows for startup recovery, independently of the recent-history display limit. Assert that old uncertain runs become completed with `OUTCOME_UNKNOWN` and remain eligible for read-only reconciliation.

3. **Replay trusts the stored digest instead of validating the loaded artifact.** Artifact integrity. [engine.ts](../src/server/engine.ts), lines 57–68, checks availability, quarantine status and target, then copies `cap.digest` into the run. It does not parse the complete capability and recompute its digest. Approval qualification and evidence export do perform that check, but replay itself does not.

   Reproduction: load a saved capability, add a harmless extra key action, retain the original digest, save it through the store, and replay. The extra action executed and the run completed `VERIFIED` with zero model calls, attributed to the old digest. This probe deliberately changed trusted stored content; it does not demonstrate an unauthenticated remote modification path. Encryption authenticates the stored envelope, but cannot catch a logical mutation saved with a stale digest.

   Parse and hash the capability before starting a browser session; reject a mismatch. Where applicable, bind approved execution to the approval-review digest as well.

**Corrections to the earlier pasted audit**

- Its claim that all remaining issues were presentational is disproved by the three probes.
- Its claim that safe purpose labels should be added to the public evidence overlooks existing code and evidence. [export-evidence.ts](../scripts/export-evidence.ts), lines 72–76, already joins steps to artifact purpose labels. Discovery has 14 purpose-bearing action entries; replay has 18 step entries. Event-level linkage could improve, but the “why” is not wholly absent.
- Its claim that the optional unattended approval gate is fully implemented is inaccurate. Evidence-backed promotion exists, and the UI labels draft runs “validation replay,” but the worker accepts drafts through the same run endpoint without an explicit validation/unattended distinction. Draft validation is necessary and intentional; do not claim the optional unattended gate until its admission rules exist. Business-write approval is a separate implemented control.
- CSS count alone does not establish a failed locator strategy. The nine CSS locators mostly use observed form attributes and scoped wizard panels. The search placeholder is vulnerable to text changes, but ambiguity and identity checks provide real safeguards. Explain these choices accurately; adding arbitrary fallback selectors could weaken safety.
- “No leaked secrets” and “nothing is public” were stronger than the available checks justified. The bounded scan and absent local remote support narrower statements.

**Work completed versus remaining product plans**

Delivered: the Electron/React workbench, local worker and Chromium sessions; Mifos/Fineract/PostgreSQL setup with pinned images and idempotent fixtures; the separate failure-injection lab; four supported Mifos task types; multimodal provider adapters; live OpenAI evidence; deterministic replay; semantic output checks; exact-preview Mifos commit approval; manual takeover; uncertain-outcome reconciliation; encrypted operational history; public evidence export; automated and browser tests.

Not delivered or not demonstrated: cloud control plane/queues, authenticated organizational access, untrusted-tenant isolation, native desktop automation, voice, signed installer/updater, Windows qualification, the proposed 72-trial provider comparison, repeat-trial reliability/cost measurements, broad version-drift qualification, or compilation of manual repairs. These are documented product ambitions, not missing assignment requirements where the assignment explicitly allows design-only treatment.

Several plans need reconciliation with the current project. `plans/reviewer-summary.md:10` still calls Mifos integration planned. `plans/implementation-blueprint.md:5` says there is no Git repository, and later sections describe proposed pnpm scripts and a cloud-oriented package layout that are not the current npm project. The current README and REPORT are more reliable implementation summaries.

The fresh-install evidence is honestly scoped to an older snapshot: **23 of its 73 recorded files now differ**, including `package.json`, the lockfile, launcher and server code. This does not invalidate that historical setup result, but it does not establish a fresh install of the audited revision. Current typecheck/build/tests passed; a new clean installation and Docker initialization were not run during this audit. Cached-download qualification also does not establish cold-install behavior.

Recommended order: fix the lab request validator, recover all unfinished runs on restart, validate replay digests, then clarify draft/unattended semantics and refresh the stale plans. After the code fixes, rerun the relevant checks and qualify a fresh checkout of the final revision. Publication and email submission remain separate handover actions.
